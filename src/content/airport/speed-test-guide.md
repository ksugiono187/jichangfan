## 一、 警惕商家的“假测速图”

在选购机场时，您经常会看到商家或推广者放出全是一片深绿色的测速图（如 Speedtest 的跑满千兆带宽截图，或是 Clash 里全部个位数延迟的截图）。

**请注意，这些指标极其容易造假，或者仅仅是在理想环境下测试的结果。**

单纯的 Ping 值低，或者在凌晨 3 点跑出 1000Mbps 的带宽，都**不能代表**这个机场在日常使用中足够稳定。评判一个节点的好坏，需要科学的测试维度。

## 二、 正确的测速指标是什么？

### 1. 真实的延迟 (TCP Ping / HTTP Ping)
在命令行中执行传统的 `ping` 命令（基于 ICMP 协议）是非常不准确的，因为很多专线和中转节点会进行“Ping 劫持”来伪造极低的延迟。
**正确的做法**是使用 Clash 或 Shadowrocket 内置的测速功能，它们执行的是 `HTTP Head` 请求或完整的 `TCP 握手`，这能真实反映您的设备连接到海外服务器并收到响应的时间。
*   **优秀**：台湾/香港节点 TCP Ping < 60ms
*   **及格**：日本/新加坡节点 TCP Ping < 100ms
*   **可用**：美国节点 TCP Ping < 180ms

### 2. 丢包率 (Packet Loss)
这是决定您打游戏是否卡顿、看视频是否频繁缓冲的**最致命指标**。
如果一个节点速度高达 500Mbps，但丢包率有 5%，那么您在加载网页时经常会遇到“卡住不动，刷新一下又好了”的情况。优质的 IPLC 专线节点丢包率应该常年保持在 **0%**。

### 3. 晚高峰单线程速度
这是检验机场底子的试金石。晚上 8:00 - 11:00，国内公网出境带宽极其拥堵。
请在这个时间段，打开 YouTube，搜索 `4K 60FPS HDR` 的风景视频。
*   右键视频选择“详细统计信息 (Stats for nerds)”。
*   查看 `Connection Speed`。如果晚高峰能稳定保持在 `50000 Kbps` (50Mbps) 以上，且 `Buffer Health` 充足不掉，说明该机场的中转线路非常扎实，没有超售。

## 三、 如何进行系统化测速？

### 1. 客户端内置功能
在 Clash 或 sing-box 的代理组界面，点击右下角的雷达/闪电图标，即可一键测试所有节点的 TCP 延迟。这能帮您快速剔除已经挂掉（Timeout）的节点。

### 2. Speedtest 国际节点测试
不要使用 Speedtest.net 的默认节点（它通常会连接您本地的运营商），请在测速前：
1. 开启代理软件的“全局模式” (Global Mode)。
2. 在 Speedtest 网页中，手动将测速服务器 (Change Server) 更改为您所连节点所在国家的服务器（例如连香港节点，就选香港的 CSL 或 HKT 服务器）。
3. 这样测出的上下行带宽，才是该节点真实的极限吞吐量。

### 3. 流媒体解锁检测工具
对于流媒体重度用户，可以使用开源的脚本（如 `RegionRestrictionCheck`）在终端中运行，或者直接在客户端中添加解锁检测模块，一键测试该节点是否被 Netflix / Disney+ 等平台拉黑。
